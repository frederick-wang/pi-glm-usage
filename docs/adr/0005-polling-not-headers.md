# 0005 — Poll the monitor endpoints; no quota headers exist

Live probing (2026-08-27, CN plan) confirmed the anthropic-compat endpoint (`/api/anthropic/v1/messages`) returns no rate-limit or quota headers — only `x-log-id`, `x-process-time`, and infra headers. There is no free, per-request, always-fresh quota signal to piggyback on, so the extension polls the monitor endpoints (`/api/monitor/usage/quota/limit`) on its own schedule: refresh on model activation, throttled refresh after each turn, a managed countdown timer between fetches, and a force-refresh command. CN `quota/limit` also returns richer fields than the global fixture suggested: all three limits carry `nextResetTime`, and the CN plan reports unit 6 (weekly) alongside unit 3 (5h) and unit 5 (MCP) — footer segmentation is driven by what is present, not by provider.
